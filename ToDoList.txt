# Linux_Maint_ToolKit - Menu-Centric Backlog (2026-03-02)

## Scope
This backlog is focused on `linux-maint menu` UX, reliability, and operator guidance.
Older roadmap items are treated as completed and replaced by this menu-forward plan.

## Priority legend
- P0: correctness/regression blockers
- P1: high-value user workflow improvements
- P2: polish, discoverability, and quality-of-life

## P0 - Fix now (menu correctness)
- Fix dialog-tag normalization in top-level and config menus so padded labels never break routing.
  - Acceptance: `LM_TUI_BACKEND=dialog linux-maint menu` can navigate all menu branches.
  - Tests: add non-interactive unit coverage for menu choice normalization/parsing.
- Fix Help docs paths in installed mode (`quickref/faq/reasons/monitors`) by resolving from installed docs share path when repo docs are absent.
  - Acceptance: installed mode help pages open successfully without repo checkout.
  - Tests: add path-resolution tests for repo and installed mode.
- Add a focused menu smoke test suite (backend-neutral) to prevent regressions in command wiring.
  - Acceptance: CI verifies each menu action maps to expected CLI command.

## P1 - Core UX features
- Add a guided "Run Wizard" in menu:
  - choose scope (`all`, `only`, `skip`)
  - choose target mode (`local`, `group`, `hosts`)
  - optional dry-run preview before execution
  - Acceptance: users can build a full run command without typing flags manually.
- Add "Status Drilldown" view:
  - filter by `status/host/monitor/reason`
  - quick toggle between table and compact
  - jump from a selected row to `explain reason` or `explain monitor`
- Add post-run "Quick Actions" screen:
  - if WARN/CRIT: offer `doctor`, `status --reasons 10`, `logs 200`, `pack-logs --redact`
  - if OK: offer `report --short`, `trend --last 10`
- Add menu settings screen (session-scoped):
  - backend, dashboard refresh, default status view mode, preferred problem/reason limits
  - writes optional config block under `~/.config/linux-maint/menu.conf` (safe fallback when absent)

## P2 - Usability polish
- Add command preview footer before execution ("Will run: linux-maint ...").
- Add keyboard shortcuts for common actions (`r` run, `s` status, `d` doctor, `h` help).
- Improve visual severity consistency across all views (OK/WARN/CRIT/UNKNOWN/SKIP colors + symbols).
- Add "recent artifacts" panel (latest summary/log/report paths + timestamps) on dashboard.
- Add copy-ready support bundle summary after `pack-logs` (path, checksum, redaction mode, gpg mode).

## QA and docs requirements for every menu feature
- Add at least one test per new menu branch and one regression test for failure/cancel paths.
- Update:
  - `docs/reference.md` (menu options/env vars)
  - `docs/QUICK_REFERENCE.md` (operator flow)
  - `docs/TUI_STYLE_GUIDE.md` (interaction and visual rules)
- Include release-note entry under next version in `docs/release_notes/`.

## Delivery order
1. P0 correctness fixes + tests
2. Run Wizard + Status Drilldown
3. Quick Actions + Settings
4. P2 polish batch and doc hardening
